Component Reusability:
======================

Same Systems Process Different Entities:
-----------------------------------------

MovementSystem:
  Processes entities with: Position + Movement
  ↓
  Works on: Player, Monster, any entity with these components

RenderSystem:
  Processes entities with: Position + Render
  ↓
  Works on: Player, Monster, Item, Stairs, any visible entity

CombatSystem:
  Processes entities with: Combat + Health
  ↓
  Works on: Player (if has Combat), Monster, any combatant


Composition Flexibility:
========================

Want a new entity type? Just compose components:

Flying Monster:
---------------
┌──────────────┐
│   Monster    │
└──────┬───────┘
       │
  ┌────┴────┬─────────┬─────────┬─────────┬─────────┐
  │         │         │         │         │         │
  ▼         ▼         ▼         ▼         ▼         ▼
Position  Render   Health   Movement  Combat    Flying
                                                    ↑
                                              Add this!

MovementSystem checks: if entity.has(Flying) → can move through walls

Component Data Structure:
==========================

Entity Structure:
-----------------
┌─────────────────────────────────┐
│         Entity                  │
├─────────────────────────────────┤
│ • id: "player-001"              │
│ • components: []                │
│ • component_map: {}             │
│ • tags: Set[]                   │
│                                 │
│ Methods:                        │
│ • add_component(component)      │
│ • get_component(type)           │
│ • has_component?(type)          │
│ • remove_component(type)        │
└─────────────────────────────────┘

Component Map (Fast Lookup):
-----------------------------
{
  :position  → PositionComponent instance
  :render    → RenderComponent instance
  :health    → HealthComponent instance
  :movement  → MovementComponent instance
  :input     → InputComponent instance
  :inventory → InventoryComponent instance
}

Access: entity.get_component(:position)
        └─> O(1) hash lookup


Benefits of Composition:
=========================

✓ Flexible
  • Any combination of components
  • No inheritance constraints

✓ Reusable
  • Same components for many entities
  • Same systems process different entities

✓ Easy to Extend
  • Add new component → add new capability
  • No need to modify existing code

✓ Testable
  • Create test entity with just needed components
  • No complex inheritance to mock

✓ Maintainable
  • Clear separation of concerns
  • Each component has single responsibility
